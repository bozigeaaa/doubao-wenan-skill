# 豆包书面图文模式（Doubao Written+Oral Mode）

建立日期：2026-09-22。适用范围：豆包（Doubao）客户端执行本仓库文案任务时**默认生效**（经 `docs/豆包执行模式.md` 调整 3 确认）；用户明确要求"短视频口播""抖音口播""口播稿"时，按 AGENTS.md 抖音口播逻辑执行。Codex 及其他客户端按 AGENTS.md 与共享规则原样执行，除非另行接入本模式。

本文件只记录经用户确认的表达层执行调整。事实与合规底线（真实性、来源可追溯、禁编造、禁夸大、禁贬损、参数边界、新闻核验）不因本文件改变。

## 模式定位

"书面+口播两用"不是第二种文案，而是同一套事实核验与植入规则下，把表达决策从"给耳朵"切到"给眼睛+耳朵"：**让人读懂且愿意读完，同时念出来不拗口**。核心是"书面底子+口播节奏"，不是"纯书面"，也不是"短视频口播"。

判断载体在路由时完成：豆包端**默认进入本模式**；用户明确要求"口播稿""短视频"时，切回抖音口播逻辑执行。

## 调整 1：起稿方式（对应 AGENTS.md 起稿条款）

- 完整稿从书面结构起稿：`新闻锚点 → 痛点 → 产品对比 → 明确推荐 → 公司落地 → 顾问式收尾`。
- 豁免 AGENTS.md"初稿直接按对着镜头说话组织"一条：本模式不先写口播版再改写，直接按书面结构组织。
- 句子按朗读节奏组织：长句短句搭配，保留逻辑层次；不为短句拆散因果、条件和责任关系。

## 调整 2：表达标准（书面审稿替代口播审查）

本模式的口播审查按"书面合格"执行，检查以下症状，其余照常：

- **查**：书面拖沓（新闻通稿腔、总结腔）、冗余复述、新闻要素堆砌、AI 腔（空泛概括、假内幕、硬广腔）、主语缺失或指代不明。
- **不查**：碎句、钩子强度、口语词配额、"像聊天不像说明书"的短句压力。
- 长句如果信息密度与逻辑层次需要，可以保留；不以短句数量作为合格标准。
- 新闻要素按"与判断直接相关"筛选：只保留支撑判断的权威主体、场景、强度与必要条件，其余（具体县份、持续日期、气象细节等）移入资料出处或删除。此条与 `generation-trigger-registry.md`"新闻要素只保留与判断直接相关的部分"一致。

## 调整 3：收尾（顾问式收尾登记为默认合法形式）

- 顾问式收尾（如"帮项目把屋面这个隐患提前避开"）在本模式为默认合法收尾，不强加点赞/关注/联系类 CTA。
- 销售导向明确时仍可联系东方骆驼；用户明确要求无 CTA 时直接结束。
- 不重复前文清单，不另起产品广告，不新增未经核实的服务或效果承诺。

## 调整 4：humanizer 使用边界

- 本模式**不逐稿调用** `$humanizer` 的口语化重构；按 `expression-craft.md` 自查"书面合格"（长句可保留、密度不塌、新闻要素按相关性筛选）。
- 高风险稿（涉及法规、精确参数、新闻、认证、强因果）保留抽查；发现症状时仍按本模式表达标准处理。
- 自查不得放宽事实命题、限定条件、因果强度与责任关系。

## 未调整部分（继续按原规则执行）

- 事实门、承诺可回答检查、受众价值检查、结构去重、反向答案检查、一句话总结检查、新闻落点检查（新闻稿）、事实复检、B2B 质量门、合规词表复检：全部保留，一个不减。
- 标题 19–36 字符、一条稿只兑现一个内容承诺、植入资格条件分支、资料出处输出：全部保留。
- 涉及新闻、政策、项目、航运、市场或竞品时变事实：仍按新闻流程联网核验。
