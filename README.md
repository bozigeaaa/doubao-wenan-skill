# 东方骆驼短视频脚本文案知识库

这是东方骆驼 / 深圳钧瀚科技用于 B2B 短视频脚本文案生成的 Codex 项目。

项目的核心目标不是堆提示词，而是把公司资料、沙特临建行业认知、产品参数、内容规则和已验证过的写法沉淀到同一个工作目录里，让 Codex 在生成脚本文案前先做资料判断和事实核实，尽量减少参数乱用、硬广腔、假现场感和不可靠表达。

## 下载后开始使用

首次使用或想让新对话了解操作方式，请先看 [新用户使用指南](docs/新用户使用指南.md)。

完整下载并解压仓库，在 Codex 中打开包含 AGENTS.md、knowledge 和隐藏目录 .agents 的文件夹。Humanizer 已随项目提供；Scrapling 技能也在项目内，首次使用需在当前电脑安装其 Python 运行依赖。

按 [新闻工具安装与自检说明](.agents/skills/scrapling/references/setup.md) 操作，或直接对 Codex 说：“准备项目内 Scrapling 抓取环境并测试，然后按新闻大类找新闻。”Humanizer 无需单独账号或 API；独立新闻日报默认采用 Scrapling + Firecrawl 双工具检索；默认工具不可用时需用另一种实际可用工具补足。服务权限与额度由每位用户自己的环境决定。

用于写稿选题的新闻流程会区分抓取情况、候选线索、事实核验与产品适配；默认展示三条合格新闻，更多结果只报告额外数量，少于三条按实际数量反馈。读取失败时按项目规则换方式或来源继续，不默认要求登录新闻网站。

## 独立新闻日报与每日自动收集

在本项目里新开一个 Codex 对话，说“收集新闻”，即可执行首轮收集与核验，并启用每日自动收集。每天北京时间09:00和14:00各启动一轮收集与核验，完成后在新闻任务中汇报；上午完成不会跳过下午。同一批次重复触发时不重复采集或推送。

每轮至少使用两种检索工具，并分别留下实际记录；默认采用 Scrapling + Firecrawl。每条新闻的核验状态、时间、结论、来源和缺失证据会直接写入 HTML。日报保留全部实际收集到的相关行业事件，不套用写稿选题的三条上限；用户自行复制选题指令到专门写稿的对话。使用方式与运行条件见 [本地新闻日报自动化](docs/local-news-automation.md)。

## 当前定位

本项目服务于以下内容方向：

- 沙特临建、工程营地、移动房屋、模块化建筑相关短视频脚本
- 东方骆驼 / EASTERN CAMEL 品牌背书内容
- 薄壁轻钢房屋、打包箱、拼装房屋等产品内容
- TBOX / K 系列移动厕所、移动卫浴、模块化卫生间内容
- SBC、Civil Defense、Salamah、SABER/SASO 等沙特行业合规科普
- 国际热点对沙特工程、营地、临建行业影响的脚本选题

默认输出目标是中文口播脚本，面向项目经理、采购负责人、营地管理者、EPC/总包、在沙特做工程的人群。

## 关键文件说明

`AGENTS.md`  
项目总规则。这里定义了脚本文案的工作流、内容类型判断、事实核实要求、输出格式、调门红线和资料出处规则。Codex 处理本项目任务时应优先遵循它。

`knowledge/`  
公司资料知识库，以 Markdown 为唯一维护版本。表格按主题拆分并保留原行号及单元格坐标；图册只保留有用的文字要点。涉及精确技术参数、规格、认证、法规等事实时，应核对相应资料正文及来源依据，格式转换不提高证据等级。公司日常业务按共享公司规则直接使用用户提供的信息，不要求逐句补交证明文件。

`knowledge/AI资料导航索引.md`  
知识库导航入口。开始写脚本前，先读它，用来判断应该读取哪些资料文件。它只导航，不替代对应 Markdown 资料正文和必要的事实核验。旧文件名到当前资料的映射见 knowledge/资料转换记录.json。

`.agents/skills/`  
本项目自定义脚本技能。不同内容方向有不同 skill，用来约束口播脚本的结构、语气、事实边界和禁止表达。

资料检索

直接按文件、章节、关键词或原表行号检索 Markdown，不再维护重复导出文本和旧格式提取脚本。

## 已有 Skills

当前项目内包含这些脚本文案技能：

- `daily-industry-news`：独立新闻收集、逐条核验、HTML 日报与本机每日补跑
- `wenan-skill`：统一入口，自动路由文案、标题、改稿和分镜任务（日常调用这一个即可）
- `global-hotspot-industry-impact-script`：国际热点对沙特临建/工程/营地行业的影响脚本
- `saudi-brand-proof-script`：沙特本地工厂、本地库存、本地交付等品牌背书脚本
- `saudi-breakout-story-script`：沙特生活、行业见闻、破圈故事类脚本
- `saudi-camp-fire-script`：SBC 801、Civil Defense、营地消防合规脚本
- `saudi-light-steel-script`：薄壁轻钢房屋、G550、围护系统、选型对比脚本
- `saudi-product-seeding-script`：产品种草和销售转化脚本
- `saudi-professional-knowledge-script`：沙特临建行业专业科普脚本
- `saudi-sanitary-unit-script`：TBOX / K 系列移动厕所、移动卫浴、卫生间脚本
- `digital-human-storyboard`：已确认口播稿的三语字幕与数字人分镜表
- `scrapling`：项目内公开新闻读取，提供独立依赖安装、自检与浏览器渲染入口
- `humanizer`：所有完整稿都进入口语与去 AI 味审查；只有表达问题实际存在时才重写，已经自然的稿件原样通过

## 推荐使用流程

标题、正文和修改在同一个项目、同一个任务中连续完成，不需要复制或转发中间交接单：

1. 用户给出话题、标题方向或已有初稿，由 `wenan-skill` 判断任务类型并选择最小必要的专项 skill。
2. Codex 读取 `AGENTS.md`、知识库导航和本次任务直接相关的资料；涉及高风险事实或时效信息时完成对应核验。
3. 系统在任务内部建立临时内容状态，明确内容承诺、判断动作或变量、必须给出的答案、可证结论、事实来源、适用边界和待解决项。公司或产品默认植入（2026-09-23 用户确认），默认记录植入资格状态；用户明确要求不写时排除。该状态用于后续步骤，不作为要求用户复制的输出。
4. 先确认已核实内容能让明确受众多一个判断、可核对依据、责任/适用边界或因果理解；只剩“提前确认、注意沟通”时不凑稿。通过后再选择合适的证明与叙述路径，生成一份完整口播稿；不套固定段落骨架，也不要求每个技法模块都启动。
5. 所有初稿都进入 `humanizer` 的口语化审查；只有存在书面腔、卡顿、重复脚手架或 AI 痕迹时才重写，已经自然顺口的稿件原样通过。
6. 交付前重新核对事实边界，并在存在近期内容记录时检查结构重复。
7. 默认交付一份最终文案；正文实际使用了新闻、参数、法规或公司能力时，在底部附 `资料出处`。

用户先选择标题方向时，确认后仍在当前任务继续生成正文，不再经过用户可见的标题交接单。现行流程也不采用额外的旧口语改写层或“原文案＋优化后文案”的固定双版本输出。

## 脚本输出原则

- 一条视频只兑现一个语义内容承诺，但不强制写成提问或问答结构。
- 标题、开场、正文中的实质性主张、条件式公司/产品内容和最后一句，必须保持同一判断动作或变量，并兑现同一必须答案。
- 默认使用沙特本地资深供应商 / 项目服务方视角。
- 公司或产品默认植入（2026-09-23 用户确认）：所有完整文案默认执行植入资格检查，用户明确要求不写时排除；植入仍须帮助回答同一内容承诺，不能只作为名称、口号或结尾广告。
- 触发并通过资格检查后，公司或产品的实质性主张必须直接回答内容承诺、提供作答所需证据，或说明该证据为何改变答案；不能只作为名称、口号或结尾广告。
- 口播要像真人对镜头说话，避免宣传册腔、公文腔和模板腔。
- 不编造案例、客户反馈、审批结果、测试报告、法规条款或市场现状。
- 不输出无法证明的绝对承诺，例如“100%安全”“一定通过验收”“完全不会返臭”。
- 涉及公司产品参数、规格、法规、国际热点或市场事实时，必须在底部列出本稿实际用到的资料出处。

## 事实核实重点

以下内容属于高风险事实，不能凭印象写：

- 钢材型号、墙体厚度、玻璃棉厚度、镀锌量、耐火时长
- 抗风、抗震、防腐、使用寿命、质保年限
- 装柜数量、打包尺寸、安装时长、产能、价格
- SBC、Civil Defense、Salamah、SABER/SASO、ZATCA 等合规表述
- 工厂面积、库存、交付能力、项目案例、客户反馈
- 当前国际热点、航运、能源、贸易、竞品和市场现状

如果资料之间出现冲突，优先查看 `knowledge/钧瀚产品优势分级分类总表_v4.md` 中的冲突登记；仍无法判断时，应向用户确认。

## 维护建议

### 知识库同步 checklist（新增/修改资料后必须过一遍）
- [ ] 新增长期复用的公司资料可放入 `knowledge/`；用户当次提供的普通业务信息可直接用于稿件，不以入库为前提。
- [ ] 新增/修改资料后，同步更新 `knowledge/AI资料导航索引.md`（文件清单、日期、非事实源标注）。
- [ ] 维护已入库的参数、产能、库存、交期、认证等资料时，同步更新 `content-state/company-claim-evidence-ledger.json` 证据台账（区分 stable_company_fact / sourced_metric / project_variable）。
- [ ] 涉及新闻、招标、项目动态的变更，同步更新 `content-state/hotspot-ledger.json` 热点台账。
- [ ] 若新增/删除/重命名 skill 或共享规则文件，同步更新 `tests/test_structure_health.py` 的引用检查与对应测试。
- [ ] 若新增/修改交接文档，先更新 `docs/README.md` 导航，避免多份文档并存无人知道主次。

### 通用维护
- 如果某类脚本反复出问题，优先把规则补进 `AGENTS.md` 或对应 skill，而不是临时改提示词。
- 公共规则只改权威文件（`AGENTS.md` 与 `.agents/skills/references/`），专项 skill 用引用继承，不复制全文。
- 如果发现某个参数存在多个版本，不要直接覆盖，应在知识库中保留冲突记录并标注待核实。
- 每次调整规则或知识库后，跑一遍 `python3 tests/run_rule_tests.py`，再提交到 GitHub，便于回溯文案工作流的演进。
