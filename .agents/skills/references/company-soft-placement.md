# 公司与产品自然植入规则

## 适用范围

公司植入是默认执行项（2026-09-23 用户确认）：所有完整文案默认植入公司，不依赖条件分支触发。公司第一次提及时写“东方骆驼”，之后再提统一用“我们”；植入完成后，结尾必须引导大家联系我们（联系话术不固定重复）。用户没有明确要求不写公司和产品时，默认执行植入；用户明确要求不写时直接排除。默认植入仍须自然回应同一内容承诺，按用户业务信息直接讲清公司做什么、提供什么和怎样解决本篇问题。

检查不等于必须植入。公司业务、产品特点和服务动作应帮助回答同一判断动作或变量，说明公司怎样回应本篇具体问题。产品本身是标题对象、选型对象或本期内容承诺时，直接展开本题需要的产品知识。

## 资料使用与植入资格

用户提供文档的核验状态按项目AGENTS.md“用户提供资料的核验状态”执行；已由用户核验的公司与产品记载不重复索证，临建行业认知单独核验。下文事实检查用于防止超出资料范围或补造事实。

先承接 `generation-trigger-registry.md` 中的对象、场景、所需答案和内容承诺，再判断公司或产品怎样参与解释或解决问题。

- 公司日常业务、产品与服务介绍，按用户提供的业务信息直接组织表达，不再要求用户逐句提交证明材料，也不把缺少单独佐证文件作为普通宣传稿的默认阻断条件。已有公司资料可用于补充内容、统一名称和处理冲突，不是用户每篇必须重新提交的手续。
- 没有用户业务信息时，按 `knowledge/AI资料导航索引.md` 定位最小相关资料；已有信息足以写常规业务介绍时，直接起稿，不强制读取全部原件或证据台账。
- 新闻、法规、认证、精确技术参数和具体项目结果按各自事实规则处理。用户提供的日常业务说明不能代替外部新闻、法规或认证的核验。
- 不自行编造客户、项目、成交数据、认证、库存或实际交付结果。具体库存、交期、排产、现场人数与项目结果，没有当期确认资料时不写；当期确认可来自用户明确提供的当前事实，无需另交单独证明文件。“库存充足、主流配置都有”等定性说法同样属于实时库存主张，不能用模糊词替代当期确认。普通稿省略不必要的实时数字，不把内部确认过程写进广告段。
- 保留项目用途、图纸、业主要求、配置、审批路径中真正决定本题结论的条件，不把可能性、比较判断或风险降低写成确定结果，不自行补造客户反馈、项目结果。不得先写未经核实的卖点，再用免责句兜底；常规业务表述按本节的用户信息入口直接使用。

植入资格看公司内容是否回应本篇问题，而非能否展示一套证明手续。没有业务关联时先换一个真实角度；仍不成立就停止植入，不补造客户痛点或项目需求。

### 新闻核验卡例外

新闻核验卡已经完成“新闻事实 → 项目判断 → 用户选定产品”的适配时，沿用选定产品和结合理由。按用户业务信息或已有资料确定产品与公司对应关系后，东方骆驼可随产品自然出现，不再重复证明公司与新闻项目存在关系，也不要求公司证据桥。

普通业务介绍沿用本文件的资料入口；公司参与、供货、安装或服务该新闻项目是另一项事实，不得由产品相关性推导。已核验新闻按原范围使用，新增新闻事实或实时进展再补充核验。

## 直接、有底气的公司表达

公司段以明确的主体和动作，直接讲公司做什么、提供什么、怎样解决本篇问题。可以突出优势、强调价值、增强宣传感；不靠虚构事实或扩大结果保证制造力度，不要求每介绍一项业务就附带限制说明。强化表达不能扩大已知的地域、配置或服务范围：“有本地生产能力”不自动包含配送和安装，“覆盖主要城市”不扩大为全境项目点。

公司和产品介绍中不再使用以下口径及其同类表达：

- “需要核实、需要评估、明确责任、确认范围”；
- “评估能承接哪些部分、确认能做到哪一步”；
- “具备相关能力、可进一步评估、提供相应支持”。

内部工作过程不进入广告段。将审核式表达改为本题相关的产品特点、公司做法或服务动作，不用换几个近义词继续保留同一套评估话术。缺少业务信息时在写作沟通中处理，不把不清楚的服务编造成事实，也不把沟通过程塞进成稿。

## 按当篇内容自然展开

公司内容可以回答问题、参与比较、解释原因、展开具体动作，或提供所需证据或解释证据为何改变答案；这些是内容关系，不是预设角色菜单或轮换剧本。

- 前文提出业务问题时，公司内容给出相应解决办法；公司出场后继续把这件事讲清楚，不转成采购指导、核对清单或泛泛的公司简介。
- 不把“新闻 → 问题 → 公司能力 → 联系我们”作为统一模板。公司可以提前出现，也可以随解释、比较或具体动作出现；品牌出现后正文仍可继续展开，不强制进入收尾。
- 不固定公司段的位置、长度、句数和讲述顺序。公司内容可以与机制写在同一段，也可以独立成段；段落形式不是植入资格。
- 不建立“某类问题就讲某项能力”的固定对应表。学习材料中的主题结构和植入位置表仅作场景示例，不用于按文案类别自动选择段落、能力或品牌位置。多样化发生在信息展开、句子衔接与公司参与解释的方式上，不只是换能力词或移动品牌位置。
- 不把参考例句作为以后反复套用的成稿模板。同一公司能力可以再次讲，每次讲到什么程度由本题需要决定，不机械罗列生产、配送、安装或全部业务。

## 成稿关联检查

只检查本篇是否讲清楚、前后是否顺畅、公司内容是否自然参与同一内容。品牌背书或公司案例可以直接以公司为主题；不要求每句话都增加独立卖点。

取消广告剥离的硬性否决：不要求删除公司名后答案一定变弱，不检查同行是否也能这样说，不要求竞争对手无法复制，也不以“换个新闻或产品名能否使用”直接否决稿件。检查公司句子有没有讲清实际做法和对本篇问题的作用。

重复检查只比较我们自己的近期稿件，依 `generation-trigger-registry.md` 检查展开、转折、广告入场与收尾；同类业务反复出现不自动失败，不为了不同硬造结论。本检查只做临时审校，不删除知识库、证据台账或原始资料。

## 口播与收尾

完整稿由项目 Humanizer 按 `expression-craft.md` 修复绕口、书面腔、跳跃、重复解释和公司段拖沓；不得把直接的业务介绍重新改成保守话术或让客户自行核对的建议。

结尾按 `expression-craft.md` 随内容变化。销售导向可直接联系东方骆驼，联系话术不固定重复，不强制让客户先提交一整套资料，不另起一段公司介绍。
