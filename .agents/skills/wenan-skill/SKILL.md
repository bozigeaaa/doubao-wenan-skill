# 文案 Skill

本 Skill 是项目内完整文案的唯一编排入口。它判断任务、读取最小必要资料、调用对应专项 Skill，并保证标题选择和文案生产在同一任务中连续进行。不要要求用户记忆专项 Skill 名称、复制初始化文本或搬运中间状态。

## 适用场景

- 选择文案大类、生成或优化标题方向。
- 从明确主题、已选标题或当前新闻生成完整中文 B2B 口播稿。
- 诊断、改写或口语化已有文案。
- 将同一任务内已确认的文案交给数字人口播分镜 Skill。

## 权威链

所有任务先读取：

1. 项目根目录 `AGENTS.md`。
2. `knowledge/AI资料导航索引.md`，再按事实类型读取本题最小必要原始资料；普通公司业务按 `company-soft-placement.md` 直接使用用户信息。
3. `.agents/skills/references/generation-trigger-registry.md`。

按任务再读取：

- 完整稿定稿：`.agents/skills/references/b2b-content-quality-gate.md`。
- 钩子与整稿表达：`.agents/skills/references/hook-pattern-library.md`、`.agents/skills/references/expression-craft.md`。
- 公司、品牌、产品或能力出现：`.agents/skills/references/company-soft-placement.md`。
- 口播审查与必要重写：`.agents/skills/humanizer/SKILL.md`。
- 新闻、政策、项目、航运、市场或竞品时变事实：对应新闻来源规则并联网核验。

`docs/` 中带日期的旧流程说明仅是历史存档，不属于生成指令，不得作为必读规则。公共执行阶段以 `generation-manifest.json` 为准，专项 Skill 只提供领域事实、资料入口和风险差异。

## 核心不变量

- 无证据，不成稿；来源只能支持它实际证明的强度。公司日常业务的来源可直接为用户信息，按 `company-soft-placement.md` 使用，不另设证明文件门槛。
- 一条完整稿只兑现一个内容承诺。标题、钩子、正文、产品或公司内容与结尾不得换题。
- 观众看完必须能用一句日常中文说出本条在讲什么（对象或场景＋判断/动作）；一句话说不清即承诺过宽或正文未兑现。简单不等于内容少：结论必须带使其可用的必要条件与边界。
- 植入资格是 `placement_eligibility` 条件分支：仅在用户明确要求公司或产品、产品本身是主题，或新闻流程已选定产品时检查；通过后才可在同一论证链中承担真实角色。
- 结构由可证结论的证明义务触发，不由话题标签、钩子类别、软植入剧本或固定段落模板触发。
- 真实性与来源优先于结构多样性；多样性只能在同样有证据支持的候选之间选择。

## 同一任务内临时内容状态

标题方向确认、用户直接给出明确标题、直接要求完整文案，都必须先建立同一份临时内容状态。该状态只在当前任务内部使用，不作为用户需要查看或传递的产物。

状态至少包含：

- 内容承诺：观众看完能带走的一句陈述。
- 观众一句话总结：锁定承诺时写成目标受众看完能直接复述的一句话（对象/场景＋判断动作）；成稿后核对该句是否成立。
- 对象与场景：标题与正文共同指向的具体对象、受众或使用场景。
- 判断动作或变量：标题要求作出的选择、时机、比较、责任或其他判断维度。
- 本稿必须给出的答案：直接回答该判断维度的可证结论。
- 答案的证据强度与适用边界：结论可用的表达强度、成立条件与不适用范围。
- 相邻但不能替代本题的问题：同项目、同产品或同领域但不能充当标题答案的议题。
- 受众任务：帮助谁完成选、查、排、算或理解原因中的哪一项。
- 受众可用结果：看完后可直接使用的判断、可核对依据、责任或适用边界，或会影响决策的因果理解。
- 可证结论：当前资料实际能证明到什么强度。
- 主张—来源—表达强度：每个实质性主张对应的来源、evidence id 和允许措辞。
- 适用边界：结论成立的条件与不适用范围。
- 用户指定篇幅：仅在用户给出目标字符/时长时，于起稿前记录该约束；未指定时采用注册表的默认口播篇幅，口播审查后复核完整度。
- 待解决项：未核实事实、资料冲突、未完成选择或其他会改变结论的问题。

临时内容状态锁定语义承诺而非可见结构：不锁定最终钩子、正文段落顺序、连接词、产品出现位置、植入句式、结尾措辞或 Humanizer 的重写方式。

### 三种入口的一致处理

- 标题方向确认：按 `generation-manifest.json` 与 `generation-trigger-registry.md` 锁定用户选定的语义承诺、标题和已核实依据；不额外输出中间卡片。
- 用户给出明确标题：按同一 manifest/registry 先检查标题承诺能否被证据直接回答，再建立同一状态；标题夸大时先降级或说明问题。
- 直接要求完整文案：可在内部比较标题，但也必须依照同一 manifest/registry 建立同一状态并通过停止门，不能从主题直接跳到正文。

`待解决项` 非空时停止成稿。能删除的无关主张直接移出；只有现有证据本身支持更窄结论时才按该边界缩窄并更新状态。会改变主题、产品、新闻对象或结论的缺口必须向用户询问一个简短问题。

## 标题流程

### 选择大类

用户只要求重新选择大类且尚未给出明确主题时，只输出：薄壁轻钢、打包箱、项目合规、项目现场与营地、采购/交付与项目管理、工程热点与新闻。输出后等待选择，不继续写标题或正文。

### 生成标题方向

先锁定目标受众、内容承诺、可证结论与证据边界，再从事实允许的入口形式生成候选。默认 6 个，只有确有不同且都可成稿时最多 8 个；不足时少给，不凑数。

每个方向输出：

- 一组承诺一致的标题。
- 本条内容承诺与可证结论。
- 最强证据及适用边界。
- 候选主信息关系。
- 新闻关联状态；新闻流程另列用户选定产品及结合理由。

标题形式可以是判断句、结果句、动作句、场景句或真实问题。标题、发布文案和正文首句不得三次复写同一问法。方向满意但标题不满意时，只改标题表面表达，不改变事实和内容承诺。

用户选定标题后，系统只更新当前任务的临时内容状态。用户可以继续说“生成文案”，无需提交任何中间材料。

## 完整文案流程

严格按以下阶段运行，阶段是否通过必须能从成稿或内部状态找到可观察证据：

1. **路由任务**：确定主专项 Skill、输出类型、受众和唯一内容承诺。
2. **核验事实**：建立主张—来源—表达强度映射；时变事实联网核验。
3. **锁定语义承诺**：统一三种入口，锁定对象与场景、判断动作或变量、必须给出的答案、答案边界和相邻不可替代议题；`待解决项` 非空就停止。
4. **承诺可回答检查**：可证结论必须直接回答锁定判断维度。资料不够时补证、改题、缩短为有限答案或停止，不用相邻知识补篇幅。
5. **受众价值检查**：明确这条已核实内容会让指定受众新增哪个判断、核对依据、责任/适用边界或因果理解。删去品牌和术语包装后若只剩泛化提醒，就换角度、缩小承诺、补证据或停止；不用 CTA、清单或篇幅伪装价值。
6. **生成初稿**：由证明义务选择主信息关系，自然完成连续论证；按 `expression-craft.md` 的“直接表达与听懂检查”直接讲事实、判断和做法，不把内部分析字段写成口播。用户明确指定字符数或时长时，在这一步前按证据边界执行该约束。
7. **设计钩子**：正文证明内容完成后，再设计由其兑现的前 0–3 秒钩子。
8. **条件式植入**：仅在 `placement_eligibility` 分支的三类入口出现时检查资格；本分支在钩子后、口播审查前执行。产品或公司按 `company-soft-placement.md` 的资料入口自然回应同一问题，不预设角色菜单、能力对应表或固定入场顺序；资格不成立时不植入。
9. **口播审查**：所有完整稿调用 `$humanizer` 按 `expression-craft.md` 检查理解、朗读、重复表达和语气，并核对问句、新闻信息和动作结尾；存在症状就重写，可删除重复脚手架并重排段落，不能改事实命题、限定条件、因果强度和责任关系。
10. **篇幅与内容覆盖复核**：按注册表的弹性篇幅规则检查内容完整度，不以字数接近默认目标作为通过条件。补写、删减或重排后重新执行口播审查。
11. **最终结构去重**：从成稿提取 `主信息关系｜证据形态｜公司角色｜结尾形式｜表层句法骨架`，再与近期已确认或已发布记录比较。只与我们自己的近期稿件比较，签名相同是复查信号，不自动否决；同一能力可以再次讲，无历史时不得声称完成跨稿去重。若去重导致改写，再执行一次口播审查。
12. **反向答案检查**：先不看标题，从最终正文提取“实际回答了什么”，与语义承诺的对象与场景、判断动作或变量、答案和边界比对；不允许靠结尾补一句掩盖变量漂移。
13. **一句话总结检查**：以目标受众身份，不看标题用一句日常中文复述本条核心；一句说不清、只说主题词、或与锁定承诺不一致时，重写正文或缩窄承诺，再重跑口播审查。
14. **新闻落点检查**：仅正文使用新闻、政策、项目进展或时变事件时触发。正文落点必须是受众的可证判断、边界或动作，新闻事实只作证据；删去新闻叙述后没有留下判断的转播式正文退回重写角度。
15. **事实复检**：对通过反向答案检查的最终表达逐项回查状态中的主张、来源和边界；任何新增或升级内容都退回事实门。
16. **B2B 质量门**：读取 `.agents/skills/references/b2b-content-quality-gate.md`，复核受众价值、标题与正文兑现、逻辑流和发布边界。
17. **合规词表复检**：读取 `.agents/skills/references/compliance-wordlist.md`，检查禁用、夸大和平台风险表达。第 16 或 17 步要求改稿时，回到口播、结构、反向答案和事实复检，不直接交付。
18. **交付**：输出一份最终口播文案和必要资料出处。只有用户要求对照时才展示内部初稿；运行回执默认隐藏，只在用户要求或流程异常时输出必要信息。

详细触发、通过与停止条件不得在此自行改写，以 `.agents/skills/references/generation-trigger-registry.md` 为准。

## 新闻任务

- 先核验原链接、发布渠道、标题、日期、主体、地点、项目阶段和复核来源；发现渠道不等于事实来源。已完成核验和选品时沿用，不重复出卡；新增实质性事实或实时进展再核验。
- 新闻与项目判断必须有可说明的传导关系。同属建筑业、同在沙特或出现相同产品词不算强关联。
- 新闻只作证据，正文落点是受众的可证判断、边界或动作；不写按时间线播报事件的转播式正文。
- 多个适配产品时先让用户选择；选定后产品须参与回答同一项目问题，但不得暗示东方骆驼已参与、供货或服务新闻项目。
- 当前产品没有合格新闻时，反馈实际检索渠道与未采用原因，并让用户选择常青议题或切换产品。
- 登录、订阅或地区限制导致无法核验时，明确受限并停止使用该事实。

## 已有文案改稿

用户直接提供的普通公司业务信息按 `company-soft-placement.md` 使用；新闻、法规、认证及具体项目结果不自动视为已核实。先区分：

- 项目内已通过事实门的确认稿：冻结事实命题、限定条件、因果强度和责任关系，再做结构或口语调整。
- 来源不明的旧稿或外部稿：先标记关键数字、法规、认证、具体项目案例、新闻和强因果等实质性主张；高风险项核验后才进入改写。
- 用户只要诊断：只报告核心结构、段落推进、报告腔、口播阻力和事实风险，不擅自改稿。

## 分镜流程

仅在当前任务已有一份明确确认的最终文案，且用户要求分镜时执行。

- `$digital-human-storyboard` 只拆分既有文案，不重新选题、改钩子、调整结构、口语化或调用 `$humanizer`。
- 默认按 `../storyboard-html-layout/SKILL.md` 交付 HTML 分镜表，保留固定七列：`镜号｜时间码｜中文字幕｜英文字幕｜阿拉伯语字幕｜分镜｜画面／素材建议`。
- 第 01 镜前 0–3 秒在画面建议中承接既有钩子；后续镜头不强制制造钩子。
- 存在多版确认稿且版本不明时，只询问要使用哪一版。

## 输出边界

- 大类阶段：只输出大类选项。
- 标题阶段：只输出真实可成稿的标题方向；新闻任务按需先输出核验卡并等待选品。
- 标题选定：更新内部状态，不输出供用户搬运的流程文档。
- 完整文案：标题、一份最终口播文案、必要资料出处。
- 分镜：默认交付可离线打开的 HTML 分镜表及链接，完整数据保留固定七列；布局读取 `../storyboard-html-layout/SKILL.md`。
- 诊断、自检、素材建议、修改说明和运行回执仅在用户要求或流程异常时输出。
